# Decisions

Design wins for UI, UX, game list and product rules. SRS wins for backend rules, security and budgets.

| #   | Decision                                                                                                                                                                                                                                                                                                                                          | Why                                                                                                                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 51 games in 9 worlds (Board Bay added), per the design catalogue in `lib/catalog.ts`. The SRS lists 45 in 8.                                                                                                                                                                                                                                      | Design wins on the game list.                                                                                                                                                                           |
| 2   | Every game is playable anytime (Daily + Free play). Phases (L, M2, M3+) only order the build.                                                                                                                                                                                                                                                     | Design product rule "Play anytime".                                                                                                                                                                     |
| 3   | `cacheComponents` is off in `next.config.ts`.                                                                                                                                                                                                                                                                                                     | Simpler data model for authenticated, per-player game routes. Edge caching of Dailies uses route-level headers instead.                                                                                 |
| 4   | Spuz is a React + CSS component (`components/brand/Spuz.tsx`), a 1:1 port of `Spuz.dc.html`, not a `.riv` file.                                                                                                                                                                                                                                   | A Rive binary can't be authored without the Rive editor. The component honours the SpuzBrain contract (mood 0..11, lookAt -1..1, still). Low-data and reduced motion render the static pose per mood.   |
| 5   | Global prefixed CSS (`styles/spuz.css`) instead of CSS Modules.                                                                                                                                                                                                                                                                                   | The template's Tailwind Turbopack loader processes every `.css` file and strips module hashing and `:global()`.                                                                                         |
| 6   | Region palette extended to 10 colours (`--reg-0..9`), first 6 exactly from the design, plus light-theme pastels and colour-blind patterns per region.                                                                                                                                                                                             | Crownfall goes up to 10 × 10 on Sundays (Weekly Mega). The design only shows 6 regions.                                                                                                                 |
| 7   | Board cell formula uses 6 px of padding, so a 390 px phone gets the designed 56 px cells.                                                                                                                                                                                                                                                         | Matches the drawn frame exactly.                                                                                                                                                                        |
| 8   | Handoff sound names (`tick_soft`, `buzz_low`, ...) alias the kit names in `spuzl-audio.js`. Added `synth`, `jump`, `land` and `spike` for Line Lane and Rage Ridge.                                                                                                                                                                               | The Handoff sound map lists them; the kit didn't have them.                                                                                                                                             |
| 9   | Every sound dispatches a `spuzl:fx` event and every haptic a `spuzl:haptic` event.                                                                                                                                                                                                                                                                | Lets E2E assert the animation + sound + haptic pairing without real audio.                                                                                                                              |
| 10  | Daily numbering starts at #1 on 2026-04-01, so the designed "Daily #214" lands on 2026-10-31.                                                                                                                                                                                                                                                     | Keeps the design's copy plausible.                                                                                                                                                                      |
| 11  | Daily clear Sparks: 5 base + 10 no-hint + 10 perfect.                                                                                                                                                                                                                                                                                             | SRS says 5 per Daily clear; the designed Results screen shows +25 for a no-hint, no-slip clear. This reconciles both. XP follows the SRS exactly (the design's +120 equals 50 + 25 + 20 + 25 speed).    |
| 12  | Level curve follows the SRS (100 × n^1.4, rounded to 10), not the design's sample "1,560 / 2,000" at level 14.                                                                                                                                                                                                                                    | SRS wins on gamification maths; the design number is illustrative.                                                                                                                                      |
| 13  | All score-, reward- and rating-changing writes go through server routes using the service role, or `svc_*` functions granted only to `service_role`. Clients have SELECT-only RLS on their own rows and public boards.                                                                                                                            | Server-authoritative rule; smallest attack surface.                                                                                                                                                     |
| 14  | Guests are Supabase anonymous users. Linking Google or email later keeps the same user id, so progress merges without loss (FR-AC-04).                                                                                                                                                                                                            | Native Supabase feature, free tier.                                                                                                                                                                     |
| 15  | Daily rollover and league rollover run in Postgres via pg_cron (00:00 and Monday 00:05 GMT).                                                                                                                                                                                                                                                      | Runs even if Vercel is cold; Vercel Hobby cron is limited.                                                                                                                                              |
| 16  | 42 badges (SRS asks for 40): 36 visible plus 6 secret.                                                                                                                                                                                                                                                                                            | Every SRS family is covered; World Explorer covers all 9 worlds including Board Bay.                                                                                                                    |
| 17  | Supabase projects `spuzl-prod` and `spuzl-preview` live in London (`eu-west-2`); Vercel functions run in London (`lhr1`) next to them.                                                                                                                                                                                                            | Closest Supabase region to Ghana and West Africa; keeps API calls from crossing the Atlantic.                                                                                                           |
| 18  | The Daily buffer is topped up by a daily Vercel cron (`/api/cron/generate`, protected by `CRON_SECRET`) instead of a GitHub Actions job.                                                                                                                                                                                                          | The GitHub secrets API is unreachable from the build environment, and Vercel already holds the keys. The workflow stays as a manual fallback.                                                           |
| 19  | Games without a hidden solution (Echo, Twins, Flinch) store a `{ "__none": true }` marker in `puzzles.solution`, decoded back to null on load.                                                                                                                                                                                                    | The column is NOT NULL; these games are verified by replay.                                                                                                                                             |
| 20  | `players.is_test` keeps players made on a deployment that shares a production database off public boards, medians and leagues. It is opt-in (`SPUZL_TEST_ACCOUNTS=1`) and off today, because staging has its own database.                                                                                                                        | A safety valve if staging ever has to share the production project.                                                                                                                                     |
| S1  | Share cards render in `next/og` from server rows by attempt or match id; the query string only picks the frame (`format`) and size (`size=small`). Card routes are public, keyed by unguessable ids.                                                                                                                                              | Link previews (WhatsApp, X) fetch without a session; scores in URLs could be forged.                                                                                                                    |
| S2  | Spuz in share cards and app icons is `lib/og/SpuzOG.tsx`, a static px port of `Spuz.tsx` for Satori. OG fonts are OFL TTFs in `assets/fonts`.                                                                                                                                                                                                     | Satori has no CSS animation, `em` or `inset`, and reads TTF/WOFF only, not WOFF2.                                                                                                                       |
| S3  | Hand-written `public/sw.js`, registered from `instrumentation-client.ts` in production builds only.                                                                                                                                                                                                                                               | Works with Turbopack without a build plugin; dev chunks are not hashed, so a cache-first worker would serve stale code.                                                                                 |
| S4  | Today's featured Dailies are prefetched by starting them (`POST /api/v1/attempts`) once per day per device; the worker caches each start response per GMT day and replays it offline.                                                                                                                                                             | The Cache API can't key POSTs, and the start response is the only puzzle payload without the solution.                                                                                                  |
| S5  | PostHog runs cookieless (memory persistence), never identifies, no autocapture or replay, and drops personal keys; Sentry sends no PII. Both are lazy imports, no-ops without env keys.                                                                                                                                                           | SRS 15.2: analytics anonymous; under-16 care; no consent banner needed for cookieless anonymous events.                                                                                                 |
| A1  | Admin sessions use their own auth cookie (`sb-spuzl-admin`) and browser client; `/api/admin` reads the `aal` claim after Supabase Auth validates the JWT and refuses anything below AAL2.                                                                                                                                                         | Signing in to /admin must never replace a player's guest session in the same browser; SRS 15.1 requires TOTP on every admin action.                                                                     |
| A2  | All admin data goes through role-checked `/api/admin` routes with the service role; admin tables have no client policies. Multi-step actions (swap, flagged review, bans) are `svc_admin_*` SQL functions that write their own audit row.                                                                                                         | One gate to test; an action and its audit row commit together.                                                                                                                                          |
| A3  | Locked Dailies are guarded by a trigger; only the swap function (transaction-local `spuzl.daily_swap`) may change their puzzle. Dailies inside 7 days auto-lock at 00:10 GMT.                                                                                                                                                                     | FR-AD-02 lock rule enforced in the database, not only in the UI.                                                                                                                                        |
| A4  | Puzzles stored by the admin console hash a key-sorted solution; the solve-check accepts either convention (or a rebuilt identical solution).                                                                                                                                                                                                      | jsonb reorders object keys, so hashes of object solutions cannot be recomputed from stored rows.                                                                                                        |
| A5  | Approved content items are scheduled through the game's own `generateAt` (the item takes the slots it reads). Guess-route games (coil, rungs, quads, minicross, seven, buried, remix) refuse until `/api/games/[game]/guess` resolves by puzzle id.                                                                                               | No per-game builder exists; the guess route rebuilds from content.ts and would grade a custom item wrong.                                                                                               |
| M1  | League ceremony rewards: promoted earns the new tier's `LEAGUE_REWARD_SPARKS`, stayed earns half of its tier's, demoted earns nothing. Granted once per league via `svc_grant_reward` (source `league`).                                                                                                                                          | SRS gives a 20 to 150 Sparks range per tier but no per-result rule. The design's "+200" is illustrative.                                                                                                |
| M2  | A player who clears a Daily midweek joins this week's league at once (`svc_join_current_league`), in last week's tier or Bronze Block, filling the fullest open group of their test/non-test kind.                                                                                                                                                | Design empty state says "Clear 1 Daily to join"; waiting until Monday would leave new players with no table for up to 7 days.                                                                           |
| M3  | Overall leaderboard for a day ranks by Dailies cleared, then total time. Under-16s never appear on city boards; school boards need a verified school; flagged attempts, banned, ranking-revoked and test players never rank.                                                                                                                      | SRS 4.10 and 15.2.                                                                                                                                                                                      |
| M4  | Streak Freeze holds stay capped at 2 (SRS), not the design's "max 3"; frozen days are logged in `streak_frozen_days` by a trigger on the rollover's Freeze spend, for the calendar.                                                                                                                                                               | SRS wins on gamification rules.                                                                                                                                                                         |
| M5  | Feed events for badges, levels (every 5th) and streak milestones are written by triggers; clears stay with the attempts service. Hidden activity and blocks are enforced in RLS and in the route.                                                                                                                                                 | One source of truth, no changes to the shared attempts service.                                                                                                                                         |
| M6  | Shop purchases run in one transaction (`svc_buy_cosmetic` calls `private.spend_sparks`) keyed by a client request id, so a retried buy is never charged twice. Hint packs add `players.practice_hints`.                                                                                                                                           | Atomic spend plus grant; idempotent under flaky 3G.                                                                                                                                                     |
| M7  | Crew clash pairs each crew weekly with the free crew closest in size, on first view of a crew page (`svc_ensure_crew_clash`); score is members' XP in the week. Teachers for School Cup must be signed-in adults (not guests); classroom mode hides Rage Ridge and photosensitive games.                                                          | No cron needed; safety for under-16 classes.                                                                                                                                                            |
| M8  | Clue Cave games (Hunch, Quickfire, Pinned, Flagged) seal their answers into the puzzle (`games/_shared/cluecave.ts`) so the board gives instant feedback and offline Dailies work. The server re-checks every finish and never trusts the client's verdict.                                                                                       | A determined player can read sealed answers from the bundle; that costs them no more than looking an answer up, and offline play matters more. Word Woods games check each guess on the server instead. |
| MP1 | Every multiplayer result is decided by the server: clients POST board states (at most 2 per second); the server computes progress with the game's own `progress()`, times finishes with the database clock (`svc_match_finish`) and applies each round once (`svc_match_commit`). Realtime carries server results and peer intents (emotes) only. | Server-authoritative rule; one atomic commit per round makes simultaneous finishes and double submits safe.                                                                                             |
| MP2 | Finishes in the same tenth of a second are a tie: fewer slips takes the round, otherwise the round is drawn. The server waits 180 ms after the first finish before deciding.                                                                                                                                                                      | Overlays M4 "Draw. 2:04.3 each"; the wait lets near ties arrive.                                                                                                                                        |
| MP3 | Clients send a heartbeat (`/matches/:id/tick`) every 2.5 s during a live round and every 8 s otherwise. 6 s without one shows the player as disconnected and pauses the Duel; 20 s abandons it (a loss).                                                                                                                                          | SRS 6 reconnect window; no server process needed, any participant's tick settles timeouts.                                                                                                              |
| MP4 | Duel XP follows the SRS (win 40, loss 10). Practice bot matches give 10 XP either way and no rating. Party: winner 30 XP, others 10. No Sparks for multiplayer.                                                                                                                                                                                   | SRS wins on gamification maths; it lists no Duel or Party Sparks. D4's Sparks tile is replaced by the prototype's Score tile.                                                                           |
| MP5 | Quick Match is closed to 13 to 15 year olds; they can still Challenge a friend and join Party rooms by code.                                                                                                                                                                                                                                      | Onboarding O1 copy: 13 to 15 is "friends and classmates only", Duels on from 16.                                                                                                                        |
| MP6 | Ably and PartyKit adapters are SDK-free (Ably: SSE + REST, PartyKit: plain WebSocket + `lib/realtime/partykit-server.ts`) with presence over heartbeat broadcasts.                                                                                                                                                                                | Thin adapters without new dependencies; selected by `NEXT_PUBLIC_REALTIME_TRANSPORT`.                                                                                                                   |
| MP7 | Board Bay moves are stored as `{ s: seat, m: move }` and applied with a per-ply seeded rng, so any state can be rebuilt from the log (takebacks). The Practice bot's seat uses the zero uuid.                                                                                                                                                     | Ludo rolls are server-side randomness; replay must be deterministic.                                                                                                                                    |
| MP8 | Duel and Party race only time-scored puzzle games with logic (no Rage Ridge, Board Bay or photosensitive games). The room picker shows Random mix, Quads, Crownfall and Sixer.                                                                                                                                                                    | Dead On (score) and Echo (photosensitive) from the P0 picker can't be raced fairly on time.                                                                                                             |
